### **PROBLEMS**

* **R1:** Use cases not defined. Who is the target audience? Errors and hallucinations by AI, leaking info, how much authority the AI model has, affected users, data sensitivity, consequences of errors, human oversight requirements and performance thresholds. These should be defined *before* comparing models, and then used to generate an evaluation framework.  
* **R2:** Which teams need to review the model, assign responsibilities, coordinate reviews, track outstanding concerns and record who has authority to approve the deployment and accept residual risk. Right now reviews happen one after the other, so they’re slow and nobody clearly owns the final decision.  
* **R3:** Each government entity checks AI models in its own way, with its own definitions, tests, and paperwork.  
* **R4:** Nobody shares what they learn. When one entity tests a model, finds problems, or learns lessons, that knowledge usually stays inside that project.  
* **R5:** A model gets approved once, but things change afterwards: the model gets updated, the provider changes its terms, the data changes, or the service is used differently.  
* **R6:** They don’t take the representation and challenges of affected users into consideration properly (Arabic speakers, people with disabilities, people with low digital literacy, frontline staff). These people also can’t easily challenge an AI decision.  
* **R7:** Different providers give them data with different ranges, benchmarks, conditions, licences, etc., so it’s not unified and hard to track. Some important info is missing completely.

---

### **SOLUTIONS**

* **S1:** A **Use-Case Card** filled in at the start: what the AI does, who it affects, data sensitivity, how much authority it has, consequence of errors, human oversight needed and pass/fail thresholds. Every test after this is based on it.  
* **S2:** An **Approval & Accountability layer** that decides which teams must review, sends reviews to them **at the same time** (not one after another), tracks open concerns and records a **named human** who approves and accepts the residual risk.  
* **S3 & S7:** A unified way to check and test models in all departments. All provider benchmarks, licences and terms are converted into **one standard format**, and any missing provider info is flagged as a risk instead of trusting marketing claims.  
* **S4:** An ecosystem of all agents interconnected, with a **shared registry** of past assessments, test results, incidents and lessons so entities can reuse each other’s verified evidence. The entity using the model still stays accountable.  
* **S5:** A repeating cycle of checking: real-time monitoring, re-checks when something changes (new triggers), a quarterly standards check, plus clear **exit/retirement rules** for when a model should be stopped.  
* **S6 & S1:** Testing usability and real-life scalability with real user scenarios in Arabic, fairness, accessibility and contestability, plus feedback from **frontline staff** and **citizen complaints/appeals**.  
* **Proportional (risk tiers):** Low-risk cases get a **fast lane** (lighter checks). High-risk cases get the full testing and more reviewers. This, together with parallel reviews and reusing past evidence, is how we reach the **80% reduction in evaluation time**.

**INPUT USE CASES**

* The user fills in the **Use-Case Card** (what the AI does, target audience, affected users, data sensitivity, how much authority the AI has, consequence of errors, human oversight, performance thresholds).

**AGENT 1: Inter-department agent**

* This agent does a risk check based on the data and tasks it’s handling and puts it in a **tier** (low / medium / high). Higher tiers get more scrutiny in the later steps; low tiers get the fast lane.  
* It also checks whether any department already has a competent existing model or agent that could do the work being proposed. If one exists, we suggest it, but only if the **context matches** (same version, similar risk tier, data, language, users). If it’s a match, we reuse its evidence and only test what’s different.  
* If not, then they:

**PUT MODEL IN (API)**

* Model API endpoint \+ model card \+ provider documents \+ licence/terms.  
* All testing uses **synthetic or masked data**, so no real government data leaks during evaluation.

**AGENT 2: Compliance and governance**

* Checks the model against the UAE AI framework, data protection rules, and rules and regulations in general.  
* Every rule is linked to its evidence, so we can show **100% compliance**.

**AGENT 3: Evaluation test creator**

* Converts the benchmarks and standards of different providers to our own standards that we set.  
* Flags any info the provider didn’t give as **“unknown \= risk”**.  
* Checks whether there are similar use cases from previous agents and, if there are, reuses past assessments. Reuse has to check that the context matches (same version, similar risk tier, data, language, users).  
* Basically creates the evaluation tests per use case, based on the Use-Case Card and the risk tier.

**AGENTS 4 & 5 WORK IN PARALLEL, SINCE THEY DON’T DEPEND ON EACH OTHER:**

**AGENT 4: Testing and red team**

* Tests and compares against the performance benchmarks (from Agent 3), and runs hallucination checks, prompt injection tests and data leakage tests. Checks procurement and supplier dependency (licence terms, data residency, what happens if the provider changes or shuts down).

**AGENT 5: User testing**

* Tests user scenarios in Arabic, fairness across groups, accessibility, and contestability (can a citizen know AI was used and appeal?), and recommends fixes for any issues that come up.  
* Includes feedback from **frontline staff** who will actually use it.

**AGENT 6: Concluder**

* Joins all results from Agents 2–5 and gives a result and recommendation (easy for non-tech people).  
* Produces an **Assurance Package**: results, assumptions, limitations, risks, and **deployment conditions** (e.g. “only for FAQ answers”, “human review if confidence is low”, “no access to personal data”).  
* It only **recommends**. It does not make the final decision.

**AGENT 7: Approval & Accountability layer**

* Decides which teams need to review based on the risk tier (business owner, cybersecurity, legal/privacy, data governance, procurement).  
* Sends the Assurance Package to all of them **at the same time**, assigns responsibilities and tracks outstanding concerns until they’re closed.  
* Records **who approved** the deployment and **who accepted the residual risk** (a named human, not the AI).  
* Handles exceptions (approved with extra conditions, or sent back).

**DEPLOY WITH CONDITIONS**

* The model goes live with the conditions from the Assurance Package, and those conditions become what Agent 8 monitors.

**AGENTS THAT WORK ALL THE TIME:**

**AGENT 8: Lifecycle monitor**

* Real-time monitoring of deployed models to make sure they work correctly and follow their deployment conditions.  
* Checks for new changes: **quarterly for standards**, and the rest **whenever new triggers happen** (model update, provider terms change, data change, the service is used differently, an incident, citizen complaints).  
* When a trigger happens, it sends the model back through the right agents for re-checking.  
* Has **exit rules**: when to pause, replace or retire a model.  
* Sends all incidents and lessons back to the **shared registry**, so other entities learn from them.
